# Migrating to 0.2.0

Version 0.2.0 assigns explicit coordinates to the semantic classification
protocol. The default remains byte-for-byte compatible with 0.1.0, so existing
configurations do not require a change.

## Lock semantic output explicitly

Repositories that want dependency upgrades to preserve their class ordering
can record the default coordinate:

```diff
 {
   type: 'semantic',
+  profile: 'wind3',
+  orderVersion: 1,
 }
```

The `wind3@1` contract includes built-in class and generated CSS-property
classification, default utility and variant groups, responsive variants, and
built-in custom groups. Future plugin releases may add profiles or versions but
will not change the output of this coordinate.

Explicit `groups`, `customGroups`, and `variants` options still override profile
defaults. The official `type: 'uno'` whole-list protocol does not use semantic
classification.

Unsupported profile names or order versions are rejected during ESLint option
validation and by the public `sortClassList` helper.
