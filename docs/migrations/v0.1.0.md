# Migrating to 0.1.0

Version 0.1.0 makes the UnoCSS ordering protocol explicit before projects rely
on it for repository-wide formatting.

## Preserve the pre-0.1 behavior

Before 0.1.0, `type: 'uno'` combined this plugin's groups and variant ordering
with UnoCSS layer, rule order, and `meta.sort` metadata. That behavior is now
named `uno-metadata`:

```diff
 {
-  type: 'uno',
+  type: 'uno-metadata',
 }
```

Apply the same rename to group and custom-group overrides. The official `uno`
protocol applies to a complete class list and is therefore not accepted as a
group-local comparator.

## Adopt the official UnoCSS protocol

Keep `type: 'uno'` to match the official UnoCSS `order` sorter. Compared with
the pre-0.1 behavior, this can produce intentional formatting changes:

- unknown utilities move before recognized utilities while retaining their
  source order
- recognized utilities use UnoCSS's native rule rank plus official variant
  weighting
- ties use locale comparison
- whitespace is collapsed and normalized like the official rule
- plugin grouping, variant, unknown, shortcut, comparator, partition, and
  whitespace options do not alter the official protocol

Both modes require a discoverable UnoCSS configuration or an explicit
`settings.unocss.configPath`.
