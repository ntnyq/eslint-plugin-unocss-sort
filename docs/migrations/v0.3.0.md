# Migrating to 0.3.0

Version 0.3.0 makes config-backed sorting honor syntax conventions resolved by
UnoCSS. Existing configurations do not require a change.

## Configured utility prefixes

When a preset applies a utility prefix, runtime analysis now removes that
prefix before semantic classification. The original token is preserved in the
fixed source:

```ts
import { presetWind3 } from '@unocss/preset-wind3'

export default {
  presets: [presetWind3({ prefix: 'uno-' })],
}
```

For example, `uno-flex`, `uno-p-2`, and `uno-text-sm` receive the same semantic
groups as their unprefixed forms.

## Variant separators

The analyzer now passes resolved `separators` through token analysis and
variant-group expansion. Separators are only interpreted outside bracket,
parenthesis, quoted, and escaped regions, so arbitrary variants and values such
as `[&:nth-child(2)]__uno-content-['a:b']` stay intact.

This behavior applies when runtime analysis loads an UnoCSS configuration.
`analysis: 'never'` and the public `sortClassList` helper without analysis keep
the deterministic `wind3@1` fallback and default `:` variant parsing.

The `UtilityAnalysis` type adds optional `base`, `prefix`, `separators`, and
`variants` fields. Existing callers that provide analysis records remain
compatible.
